LOCAL HTTP / HTTPS PACKET COMPARISON
===================================

Use only this localhost lab and dummy accounts. Start HTTPS as documented in
README.md, then open https://127.0.0.1:8443/login/. The self-signed certificate
warning is expected; proceed only for this exact local dummy-data lab address.
The footer should show HTTPS and the account page should show Secure enabled.

For the comparison, start HTTP on 127.0.0.1:8000 using the README instructions.
Use a dummy main-site account and repeat the same login in each mode.

When you choose to run Wireshark, select the Npcap loopback interface. Limit
collection with this capture filter:

    host 127.0.0.1 and (tcp port 8000 or tcp port 8443)

Start capture immediately before the dummy logins and stop immediately after.
HTTP display filter: tcp.port == 8000 && http
HTTPS display filter: tcp.port == 8443 && tls
If needed use Decode As to associate port 8443 with TLS.

HTTP: Follow TCP Stream shows readable headers and form fields, including the
dummy password. HTTPS: expect a TLS handshake and encrypted Application Data;
Follow TCP Stream does not reveal the form body or session cookie. IP addresses,
ports, packet sizes, and timing remain visible. Some handshake metadata remains
visible too. TLS protects application data, not every byte of every packet.

Do not configure TLS session-key logging or import decryption secrets for this
comparison. Developer Tools can still show form data: it is inside the browser,
before encryption, and does not show that a network observer can read it.
This demonstration does not need Burp. A trusted local Burp certificate lets
Burp terminate and inspect HTTPS as a proxy; that does not mean TLS was broken.

Suggested evidence: HTTP form data, HTTPS handshake/Application Data, and the
HTTPS account page with transport and Secure cookie indicators. Explain that
password hashing protects storage while TLS protects data in transit. The
self-signed certificate encrypts traffic but lacks normal browser trust.

Stop both servers and the capture afterward. Keep only dummy-data evidence.
This setup is intentionally confined to localhost and must not be published.
