Read-only setup guide

Switching between HTTP and HTTPS

These instructions identify the files and server configuration to change manually. This page cannot enable or disable HTTPS.

Keep both modes local. Bind the Django backend and any TLS proxy to 127.0.0.1. Do not expose the intentionally vulnerable lab to a LAN or the internet.

Where to make changes

Two configurations work together

betasecengineering/settings.py
DJANGO_SECURE_COOKIES controls the Secure flag on the session and CSRF cookies. It does not create an HTTPS connection.
Your local web server configuration
serve_https.py provides the loopback-only TLS listener and serves the application directly. betasecengineering/settings_https.py enables Secure cookies automatically. No reverse proxy is required.

HTTP mode

Serve Django directly

  1. Stop or disable the HTTPS listener in your local web server configuration.
  2. Set DJANGO_SECURE_COOKIES=0 before starting Django.
  3. Run the backend on 127.0.0.1:8000 and open http://127.0.0.1:8000/.

HTTPS mode

Run the local TLS launcher

  1. From the project directory, run pwsh -File .\create-local-cert.ps1 once to create a 30-day self-signed localhost certificate.
  2. Run python serve_https.py using your Django Python interpreter, then open https://127.0.0.1:8443/.
  3. Expect a browser certificate warning. Proceed only at this exact localhost address with dummy data. Traffic is encrypted, but the self-signed certificate does not provide normal browser trust. No system trust settings are changed.
  4. Secure cookies are enabled automatically. Stop with Ctrl+C; restart after code changes.

Verification

Check the account page

Sign in through the main login and open the account page. The transport badge should match HTTP or HTTPS, and the Secure cookie status should match the selected mode. Use only dummy local accounts. This direct TLS launcher does not trust X-Forwarded-Proto: https headers.
