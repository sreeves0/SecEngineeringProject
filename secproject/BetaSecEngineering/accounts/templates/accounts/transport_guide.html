Read-only setup guide

Switching between HTTP and HTTPS

These instructions identify the files and server configuration to change manually. This page cannot enable or disable HTTPS.

Keep both modes local. Bind the Django backend and any TLS proxy to 127.0.0.1. Do not expose the intentionally vulnerable lab to a LAN or the internet.

Where to make changes

Two configurations work together

betasecengineering/settings.py
DJANGO_SECURE_COOKIES controls the Secure flag on the session and CSRF cookies. It does not create an HTTPS connection.
Your local web server configuration
A Caddyfile, nginx.conf, Apache virtual host, or equivalent must define the HTTPS listener, local certificate, and reverse proxy. This repository does not currently include one.

HTTP mode

Serve Django directly

  1. Stop or disable the HTTPS listener in your local web server configuration.
  2. Set DJANGO_SECURE_COOKIES=0 before starting Django.
  3. Run the backend on 127.0.0.1:8000 and open http://127.0.0.1:8000/.

HTTPS mode

Terminate TLS in a local web server

  1. Keep Django listening only on 127.0.0.1:8000.
  2. In the local web server file, add an HTTPS listener on a loopback address, configure a trusted local certificate and private key, and proxy requests to http://127.0.0.1:8000.
  3. Configure the proxy to send X-Forwarded-Proto: https. If Django is meant to trust that local proxy, add SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https') to betasecengineering/settings.py.
  4. Set DJANGO_SECURE_COOKIES=1, restart Django and the local web server, then open the proxy's HTTPS URL.

Verification

Check the account page

Sign in through the main login and open the account page. The transport badge should match HTTP or HTTPS, and the Secure cookie status should match DJANGO_SECURE_COOKIES. Use only dummy local accounts.
